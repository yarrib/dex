# [Stability] fix(release): reliable docs redeploy on release + draft GitHub Releases (#61)

**Commit:** `9a70850` · **Author:** yarrib · **Date:** 2026-06-04 · **Area:** Docs, CI & Release

## Why

After v0.2.3 shipped, the changelog on the docs site left the released
commits
under **[Unreleased]**. Root cause: the `workflow_run`-based docs
redeploy added
in #60 **never fires**. `tag-on-merge` dispatches `release.yml` using
`GITHUB_TOKEN`, and GitHub's loop-prevention rule means a run *initiated
by*
`GITHUB_TOKEN` emits **no `workflow_run` event** — so `docs.yml` can't
chain off
Release completing. The only docs deploy was the merge-push one, which
ran before
the tag existed.

## Fix

- **`tag-on-merge.yml`**: after pushing the tag, also `gh workflow run
docs.yml`.
A `workflow_dispatch` made with `GITHUB_TOKEN` *does* start a run
(that's how
`release.yml` already gets dispatched), and by then the tag exists, so
the
changelog regenerates with the released commits under their version
heading.
- **`docs.yml`**: drop the dead `workflow_run` trigger; keep `push:
main` (for the
  Unreleased section) and `workflow_dispatch`.
- **`release.yml`**: publish the GitHub Release as a **draft** (`draft:
true`) —
binaries + tag are still automatic, but a human reviews and clicks
**Publish**
  before it goes public.
- Docs: `docs/releasing.md` and `.claude/commands/release.md` updated
for both.
