# [Dependency] docs: correct the release skill for the tag-driven process

**Commit:** `b11b234` · **Author:** yarrib · **Date:** 2026-06-03 · **Area:** Foundation & Architecture

The `.claude/commands/release.md` skill was stale and described a
process that no longer exists:

- referenced `pyproject.toml` and "platform wheels" — dex ships a single
native Rust binary, no Python/wheels
- referenced a `version.yml` "auto-release on merge" workflow — there is
no such workflow (only `ci.yml`, `docs.yml`, `release.yml`)
- referenced `scripts/bump-version.py` — the script is
`scripts/bump-version.sh`
- implied `make bump-*` tags and pushes directly — it only bumps +
commits; `main` is protected so the bump goes through a PR, and `make
tag-release` is a separate step run on `main` after merge

### This PR
Rewrites the skill to match the actual flow: bump on a release branch →
PR → merge → `make tag-release` (or `workflow_dispatch`) → `release.yml`
validates the tag against `Cargo.toml`, builds the four native binaries
(linux x86_64/aarch64 musl, macos x86_64/aarch64), and publishes the
GitHub Release. Troubleshooting updated to match (including the
version/tag-mismatch failure).

Docs-only; no code changes.
